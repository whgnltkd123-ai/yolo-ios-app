# 추적 · 채증 갤러리 · 가입자 알림

기존 모델을 유지한 기능 변경이다. 학습 성능 개선이나 실제 기기 검증 완료를 뜻하지 않는다.

## 앱에서 사용하는 방법

- 화면의 ‘추적 · 채증 · 알림’에서 추적과 자동 채증을 각각 켜고 끈다. 기본값은 꺼짐이다.
- 추적은 현재 화면의 대상 번호와 이동 경로다. 화면 밖 대상을 찾거나 카메라를 자동 회전하지 않는다. 줌·렌즈·모델 변경, 긴 누락, 모호한 연결에서는 판단 근거를 초기화한다.
- 드론은 70점 이상 7회 연속, 새·비행기는 60점 이상 3회 연속 관측에서 표시한다. 구분이 불안정하면 미확인 물체로 표시한다. 작은 드론의 기존 크기 제한을 유지한다. 점수는 실제 정답 확률이 아니다.
- 자동 채증은 해당 추론의 사진과 표시 사진, 시각·분류·점수를 앱 전용 갤러리에 보관한다. 사진 앱이나 서버에 자동 업로드하지 않는다. 사진 저장은 재인코딩된 추론 프레임이며 영상 녹화나 법적 원본 인증 기능은 아니다.
- ‘채증 갤러리’에서 항목을 열어 ‘사진 앱에 저장’, 사진·정보 내보내기, 삭제를 선택한다. 사진 권한은 수동 저장 시에만 요청한다. 자동 채증 OFF는 기존 자료를 삭제하지 않는다.
- 같은 대상·상태는 30초, 전체는 5초 저장 간격을 둔다. 500MB 또는 남은 공간 부족 시 자동 채증을 끄며 기존 자료를 자동 삭제하지 않는다. 갤러리를 보는 동안은 새 채증을 멈춘다.
- 갤러리는 Application Support의 앱 전용 공간에 있으며 사진 앱/Files에서 직접 보이지 않는다. 클라우드 백업에서 제외한다. 앱 삭제 시 사라지므로 필요한 자료를 먼저 내보낸다.
- 앱을 백그라운드로 보내면 탐지·채증·발송을 멈춘다. 원격 푸시 수신은 iOS가 처리한다.

## 여러 가입자 푸시

앱과 같은 그룹에 가입한 휴대폰에 알림을 보낸다. 초대코드는 일회용이며 운영자가 발급한다. 수신 전용 가입자와 발송 권한이 있는 관측 기기를 분리한다. 이메일/전화번호/SMS는 사용하지 않는다.

서버 구현은 services/drone-alerts/server.mjs다. Node 24에서 서버 폴더를 작업 경로로 사용한다.

1. 실제 운영에는 HTTPS 도메인/서버와 Apple Developer의 Push Notifications 권한이 있는 앱 ID·프로비저닝·서명이 필요하다. Apple APNs 키를 채팅이나 저장소에 넣지 않는다.
2. 서버의 비밀 설정으로 APNS_KEY_FILE(.p8 경로), APNS_KEY_ID, APNS_TEAM_ID, APNS_TOPIC(서명 앱의 bundle ID), APNS_ENVIRONMENT(sandbox 또는 production), DATABASE_PATH를 지정한다. p8와 DB 파일은 운영자만 읽도록 설정한다.
3. node server.mjs로 실행한다. 기본은 127.0.0.1:8080이며 HTTPS reverse proxy 뒤에 둔다. 프록시에서 연결/요청 속도 제한을 적용하고 요청 본문·Authorization 로그는 끈다. 현재 서버는 배포되지 않았다.
4. 같은 DB 설정에서 node server.mjs invite GROUP publisher 또는 subscriber로 일회용 코드(24시간)를 발급한다. 필요한 사람에게만 전달한다. 앱에서 서버 주소·초대코드로 가입하고 알림을 허용한다. 가입은 90일 유효하며 만료 시 다시 초대한다.
5. 발송 기기에서 ‘가입자에게 전송’을 켠다. 발송 ON은 앱 재실행 시 유지하지 않는다. 안정된 드론 판정만 전송하며 사진·위치는 보내지 않는다.
6. 채널당 100기기, 발송 기기당 10초/동일 추적 대상 60초 간격이다. 서버는 이벤트 ID 중복을 차단한다. TTL 30초 알림이며 오래된 알림을 재전송하지 않는다.
7. APNs accepted는 Apple 접수이지 실제 화면 표시/진동 확인이 아니다. iOS 알림·집중 모드·소리 설정과 연결 상태에 따라 달라진다. 핵심 경보의 유일한 전달 수단으로 검증된 상태가 아니다.

기존 unsigned IPA/Sideloadly 서명만으로 원격 푸시 가능하다고 보장하지 않는다. 푸시용 서명에서는 YOLOiOSApp/PushNotifications.entitlements를 CODE_SIGN_ENTITLEMENTS로 지정하고 APS_ENVIRONMENT를 해당 프로비저닝에 맞춘다. 일반 unsigned 빌드에서는 푸시 entitlement를 강제하지 않는다.

로컬 검증: node --test services/drone-alerts/server.test.mjs. 실제 APNs/휴대폰 알림을 보내지 않는 테스트다.

## 별도 블루투스 진동 수신기

BLE 수신기와 iPhone Core Bluetooth 연동은 가능하다. 일반 블루투스 페어링만으로 모든 진동 기기를 제어할 수는 없다. 제품이나 직접 제작한 펌웨어의 쓰기 가능한 GATT 명령 규격이 필요하다. 아직 제품이 없으므로 현재 앱에는 검증되지 않은 BLE 제어를 넣지 않았다.

전용 수신기 계약 초안:
- 보안 연결·bonding 후 사용자가 선택한 기기 한 대만 연결한다.
- 고유 service UUID와 command(write-with-response), status(notify) characteristic을 정의한다.
- 명령에 버전, 이벤트 순번, 패턴, 지속 시간(최대 2초)을 넣는다. 중복 순번은 재진동하지 않는다.
- 수신기는 ACK/배터리/오류를 응답하고 연결이 끊기거나 명령이 만료되면 모터를 끈다. 앱은 ‘연결됨’과 ‘실제 진동 ACK’를 구분한다.
- 수동 진동 시험과 연결 끊김/재연결/백그라운드 시험 후 제품별 구현을 확정한다. 아직 하드웨어 작동 검증은 없다.

## 검증 범위

Node 인증/역할/그룹 격리, 초대코드 소모, 중복·빈도 제한, 구독 해제, 실패 토큰 정리와 만료를 시험한다. AerialTrackerTests는 누락·교차 모호성·점수·상태 전환의 회귀 시험이다.

실제 iPhone에서 자동 채증 ON/OFF, 갤러리 열기/재실행, 선택 저장·권한 거부, 공유·삭제·용량 제한, 줌·렌즈 전환, 배경 전환, 두 기기의 푸시 접수/수신을 확인해야 한다. Windows에서 iOS 기기 검증을 대신할 수 없다.
